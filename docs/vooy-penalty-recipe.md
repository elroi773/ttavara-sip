# vooy Recipe: 확인된 지옥맛 후보로 벌칙 추첨

아래 지침을 vooy의 단체방 벌칙 Recipe에 적용합니다. 이 파일 작성만으로 vooy에 자동 반영되지는 않습니다.

## 실행 지침

1. 서로 다른 참여자 2명 이상의 이름을 확인해 `participants`로 구성한다. 사용자가 직접 알려준 이름으로도 진행하며 실제 단체방 멤버를 검증한 것으로 표현하지 않는다.
2. 요기요 MCP로 대상 지역의 매장을 검색하고, 해당 매장의 실제 음료 메뉴와 가격을 조회한다.
3. **각 메뉴에 적용 가능한 추가 옵션 목록과 옵션 가격까지 직접 조회한다.** 다른 메뉴나 다른 매장에서 본 옵션을 사용할 수 있다고 추정하지 않는다. 기본 메뉴만 확인되었거나 옵션 목록·가격·적용 가능 여부를 확인할 수 없으면 후보에서 제외한다.
4. 조회 결과에 존재하는 메뉴와 추가 옵션만 사용해 독특하고 호불호가 강한 조합을 구성한다. 재료·시럽·샷 등을 임의로 만들지 않는다. 선택한 모든 옵션을 함께 적용할 수 있는지, 옵션 선택 제한 및 필수 선택 조건도 충족하는지 확인한다. 품절·판매 중지 또는 선택 불가인 메뉴·옵션은 제외한다.
5. **벌칙 음료의 기본 난이도는 지옥맛(5/5)으로 고정한다.** 아래 필수 조건을 모두 통과한 조합만 5점으로 평가한다. 평범한 단맛 추가, 흔한 카페 조합, 희귀함·색깔·식감·가격·옵션 개수의 가산점만으로 5점을 채우지 않는다. 수량을 과도하게 늘리는 방식이나 먹을 수 없는 재료를 사용하지 않는다. 조건에 맞는 후보가 없으면 난이도를 낮추지 않고 후보 없음을 안내한다.
6. 실제 확인된 매장·메뉴·기본 가격을 `storeName`, `menuName`, `basePrice`에 그대로 옮긴다. `menuVerified`는 요기요 MCP에서 확인을 마친 경우에만 `true`로 설정한다. 선택한 각 옵션의 실제 이름·추가 가격을 `options`에 넣고, 해당 메뉴에서 그 옵션의 적용 가능 여부와 가격을 확인했을 때만 `verified: true`로 설정한다. 모든 가격은 원 단위 정수이며 무료 옵션은 0원이다. `options`의 각 항목은 한 번 선택하는 옵션이며 가격도 그 선택의 추가 금액이다.
7. **요기요에서 확인된 5점 후보만** `draw_penalty`의 `candidates`로 전달한다. 후보는 요청당 최대 50개, 추가 옵션은 후보당 최대 20개이며 전체 HTTP 본문은 32 KiB 이하여야 한다. `tasteKeyword`로 지옥맛 후보를 일반 취향 음료로 대체하지 않는다. 필요한 검색 조건은 후보를 구성하기 전에 적용한다.
8. 후보를 만들 수 없으면 추첨 도구를 호출하지 않고 후보 없음을 안내한다. 서버에 빈 배열을 전달한 경우에는 다음 오류 계약을 따른다. `NO_PENALTY_CANDIDATES` 응답은 사용자에게 **"주문 가능한 벌칙 음료 후보 없음"**으로 전달하고 종료한다. `error.issues`가 있으면 함께 확인해 입력에서 누락되거나 조건에 맞지 않은 필드를 설명한다. 일반 레시피나 DB 예시를 대신 추첨하지 않고, 재시도를 위해 확인 여부나 점수를 꾸미지 않는다.
9. 추첨 성공 시 `winner`, `candidate.storeName`, `candidate.menuName`, 선택 옵션과 각 가격, `totalPrice`를 알린다. 이 서버의 호출은 주문을 실행하지 않는다. 실제 주문 직전의 최종 가격·메뉴 상태·추가 요금은 요기요 MCP에서 다시 확인한다.

## 기본 지옥맛의 필수 조건 — 시럽 중심

- 같은 메뉴에서 실제로 동시에 선택 가능한 서로 다른 향의 시럽 2~3종을 우선 탐색한다. 시럽의 정확한 이름·가격·추가 또는 변경 여부·선택 제한을 확인한다. 샷·크림·토핑은 보조 옵션이며 필수가 아니다.
- 시럽끼리 또는 시럽 조합과 베이스가 만드는 강한 맛·향의 부조화를 구체적으로 설명할 수 있어야 한다. 독립적인 강한 충돌 2개와 옵션별 개별 충돌은 요구하지 않는다. 조합 전체의 강한 부조화 하나도 평가할 수 있다.
- 시럽 개수만으로 자동 5점을 주지 않는다. 바닐라+헤이즐넛 라떼 등 자연스러운 디저트 조합과 단맛만 늘리는 조합은 제외한다. 강한 부조화를 설명할 근거가 없으면 최대 4점이며 추첨에서 제외한다. +3·+2·+1 누적 점수는 사용하지 않는다.
- 꿀 토마토 주스+에스프레소 샷+헤이즐넛 시럽은 기존의 약한 조합이므로 계속 제외한다. 토마토 슬러시+꿀, 홍차+꿀도 제외한다.
- 단일 선택 그룹의 시럽을 함께 선택할 수 있다고 가정하지 않는다. 필수 선택·최대 선택 수·품절을 확인한다. 없는 시럽·요청사항·과도한 양에 기대지 않는다. 적격 후보가 없으면 난이도를 낮추거나 점수를 꾸미지 않는다.
- 결과에는 "기본 난이도: 지옥맛(5/5)", 시럽 이름과 베이스, 구체적인 부조화 이유를 표시한다. 5점은 요기요 값이 아닌 Recipe의 주관적 평가임을 구분한다.

이 조건은 **vooy Recipe의 후보 생성·평가 규칙**이다. 서버 입력 계약의 옵션 최소 1개와 5점 필터는 기존 호출 호환성을 위해 유지하며, 서버가 맛을 독립적으로 판정하지는 않는다. 이 Recipe는 확인된 시럽 2~3종을 중심으로 위 기준을 통과한 후보만 전달한다.

## Tool 입력 계약

```ts
{
  participants: string[];
  tasteKeyword?: '달콤쌉싸름' | '시원상콤' | '고소담백' | '깔끔시원' | '랜덤';
  candidates?: Array<{
    storeName: string;
    menuName: string;
    basePrice: number;
    menuVerified?: boolean; // 생략하면 false
    weirdnessScore: number; // 0~5 정수, 5만 추첨
    options?: Array<{       // 생략하거나 비어 있으면 후보 제외
      name: string;
      price: number;
      verified?: boolean;  // 생략하면 false
    }>;
  }>;
}
```

서버는 `menuVerified === true`, `options.length > 0`, **모든** 옵션의 `verified === true`, `weirdnessScore === 5`를 만족하는 후보만 추첨한다. 하나라도 확인되지 않은 옵션이 포함되면 그 옵션만 제거하지 않고 후보 조합 전체를 제외한다. 잘못된 이름·가격·자료형 등은 `VALIDATION_ERROR`로 반환한다.

`candidates`를 생략하거나 빈 배열로 전달하거나, 필터링 후 후보가 0개가 되면 모두 `NO_PENALTY_CANDIDATES`와 "주문 가능한 벌칙 음료 후보 없음"을 반환한다. 기존 `tasteKeyword` 입력은 호출 호환성을 위해 허용하지만 후보 필터링에는 사용하지 않는다. 등록·추천·목록·상세 조회 및 기존 SQLite 레시피 데이터는 그대로 유지한다.

확인 플래그는 **vooy가 제공한 확인 결과에 대한 선언**이다. 서버는 요기요 API/MCP를 호출하지 않으므로 플래그의 진위를 독립적으로 검증하거나, 맛을 평가하거나, 실제 주문 가능성을 보증하지 않는다. 따라서 위의 확인 절차와 5점 기준을 Recipe에서 반드시 지켜야 한다.

## vooy에서 확인할 실제 호출 인자

메뉴를 조회했다는 대화 내용은 Tool 인자로 자동 전달되지 않는다. 요기요 MCP 결과를 확인한 뒤 위 계약에 맞춰 별도의 `candidates` 배열을 구성해야 한다. `draw_penalty`의 `arguments`는 다음 구조다. **아래 매장·메뉴·가격은 합성 테스트 데이터이며 운영 호출에 복사하지 않는다.** 실제 조회 값과 근거 있는 점수로 바꾼다.

```json
{
  "participants": ["민수", "지연", "철수"],
  "candidates": [
    {
      "storeName": "합성 테스트 매장",
      "menuName": "합성 테스트 토마토 음료",
      "basePrice": 4000,
      "menuVerified": true,
      "weirdnessScore": 5,
      "options": [
        { "name": "합성 테스트 캐러멜 시럽", "price": 500, "verified": true },
        { "name": "합성 테스트 민트 시럽", "price": 0, "verified": true }
      ]
    }
  ]
}
```

확인 플래그는 문자열 `"true"`가 아닌 JSON 불리언 `true`, 점수와 가격은 문자열이 아닌 숫자다. `weirdnessScore`는 후보 안에, `menuVerified`는 메뉴 후보 안에, `verified`는 **각 옵션 안에** 둔다. 일반 레시피의 `baseDrink`/`modifiers`나 `get_recipe`의 `orderPayload`는 이 입력 계약과 다르므로 그대로 넘길 수 없다. `candidates`는 단일 객체나 `{recipes: [...]}`로 감싼 객체가 아닌 배열이어야 한다.

## "후보 없음" 원인 구별

참조 대화의 간략한 규칙은 "실제 확인된 5점 후보를 전달"하도록 하지만 확인 플래그와 정확한 JSON 구조까지 지정하지 않는다. 로컬 스키마·필터·기존 테스트와 이 문서의 상세 계약은 서로 일치한다. 실행 중인 vooy Recipe가 간략한 규칙만 사용하면 다음 누락이 생길 수 있다. 당시 `tools/call.arguments` 원문이 없으므로 어떤 누락이 실제 발생했는지는 확정할 수 없다.

| 호출 인자 상태 | 서버 처리 |
| --- | --- |
| `candidates` 생략 또는 `[]` | `NO_PENALTY_CANDIDATES`; 이전 요기요 조회 결과나 DB에서 자동으로 후보를 가져오지 않음 |
| `menuVerified` 생략 또는 `false` | 해당 후보 제외 |
| `options` 생략 또는 `[]` | 해당 후보 제외 |
| 옵션 중 하나라도 `verified` 생략 또는 `false` | 후보 조합 전체 제외 |
| 정수 `weirdnessScore`가 0~4 | 해당 후보 제외; 메뉴 존재 여부와 별개의 조건 |
| `weirdnessScore` 생략, 문자열 점수/확인 플래그/가격, 잘못된 후보 구조 | `VALIDATION_ERROR`와 `error.issues`; 후보 없음과 구별 |

후보를 전달했으나 전부 제외되면 기존 오류 코드·메시지를 유지하고 `error.issues`에 탈락 원인을 추가한다. 예를 들어 메뉴와 첫 옵션의 확인 플래그가 빠졌다면 `candidates.0.menuVerified`, `candidates.0.options.0.verified` 경로가 반환된다. 후보 자체가 생략되거나 빈 배열이면 기존 응답 그대로이며 `issues`는 없다. `issues`는 파싱된 값 기준이므로 명시적 `false`와 생략은 구별하지 않는다.

vooy 실행 기록에서 **실제로 보낸 `draw_penalty` 인자와 원본 오류 응답**을 확인한다. 적격 후보를 보냈는데 계속 실패하면 연결된 MCP 주소의 `tools/list`에 위 `candidates`와 중첩 필드가 공개되는지 확인한다. 수정된 서버를 빌드한 뒤 기존과 같은 `DATABASE_PATH`와 환경 설정으로 재시작하고 vooy에서 도구 목록을 새로 불러온다. 로컬 빌드만으로 이미 실행 중인 프로세스나 vooy Recipe가 바뀌지는 않는다. 위 상세 지침도 Recipe Studio에 별도로 반영해야 한다.

2026-10-25 추가 운영 점검에서 vooy에 저장된 `draw_penalty` 설명이 여전히 "저장된 음료 한 개를 무작위로 뽑습니다"인 초기 버전임을 확인했다. 실행 중인 서버의 설명은 후보 기반 추첨으로 갱신되어 있었으므로, 서버와 vooy에 저장된 도구 정보 사이의 불일치가 확인된 것이다. vooy의 **서비스 연결 → 따바라 한모금 SIP → 설정 → 도구 설정 저장**에서 기존 주소와 5개 도구 선택을 유지해 저장한 뒤, 설정을 다시 열어 `candidates`, 확인 플래그, `error.issues`가 포함된 새 설명으로 바뀌었음을 확인했다. Recipe Studio에는 기존 추천·등록·조회·참여자 규칙을 보존하고 상세 입력 계약을 추가했으며, 새로고침 후에도 저장되어 있음을 확인했다. 당시 실패 요청의 인자 원문 자체는 확보하지 않았으므로 실제 누락 필드까지 확정한 것은 아니다.

## 테스트 데이터 주의

프로젝트의 자동화 테스트와 로컬 호출 검증에 사용하는 매장·메뉴·가격은 합성 테스트 데이터다. 테스트의 `true` 플래그는 필터링 동작을 검증하기 위한 것이며 실제 요기요 검색 결과나 주문 가능한 메뉴를 뜻하지 않는다. 해당 데이터를 운영 후보로 사용하지 않는다.
